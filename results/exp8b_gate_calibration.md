# 实验 8b：`UncertaintyGate` 的项审计、权重拟合与阈值校准

> 要回答的问题：exp8 报出"占 0.75 权重的两项是坏的、融合分没有校准"之后，
> **这个门控到底该怎么定权重、怎么定阈值？**
>
> 数据：`results/exp8_raw.jsonl`（exp8 的 94 题逐题结果，**不调 LLM，零成本可复跑**）
> 结果：`results/exp8b_gate_calibration.json`
> 代码：`scripts/exp8b_gate_calibration.py` · 自测：`scripts/selftest_guards.py` 第 [20] 组

## 结论先说

1. **发现并修掉一个真 bug：出厂默认 `threshold=0.5` 不可达，这道闸门从来没触发过。**
   三项权重 (0.4, 0.35, 0.25) 下风险分的**实际可达区间是 [0.053, 0.401]**，
   上界 0.401 < 0.5。整条 exp9 消融 **2445 次运行里 `uncertainty` 判出 warn 的次数是 0** ——
   B1 名为「+风控四闸门」，实际只有三道在工作。
   这与 `_top_scores()` 读错键、`n_final_review` 漏传 `confidence` 是同一类
   **"声明了但没接线"**：不报错、指标不变、静默失效。本次已把它变成自测第 [20] 组。

2. **T2（无证据项）在本语料上恒为 0，它的权重**不可辨识**。**
   引用数 0 条的样本 **0/94**，所以 T2 ≡ 0 —— 无论权重填多少，排序结果一模一样。
   这不是"权重选错了"，是"这个权重不存在"。它的实际代价是把可达上界从 1.0 砍到 0.401。
   （**不删它**：T2 防的是"证据契约被违反"这个真实故障模式，只是本语料没触发。
   删掉等于按语料拟合。保留 + 如实披露，是这里的正确选择。）

3. **dev 上拟合权重：能拟合出方向，但拟合结果在 test 上无可证实的增益。**
   - dev 最优把 T1:T3 的比例从出厂的 **0.615:0.385** 拉到 **0.29:0.71** ——
     即"下调自评置信度、上调检索分"，与 exp8 的方向诊断完全一致；
   - 置换检验 p < 0.0005：**这个 dev 最优不是纯噪声**；
   - 但到 test 上，配对 bootstrap 的 AUC 增量 = **+0.025，95% CI [−0.092, +0.125]，含 0**。
   → **不采纳拟合权重。** 47 题的 dev 上，一个"确实不是噪声"的拟合仍然不足以在
   47 题的 test 上兑现。这条负面结论和正面结论一样重要。

4. **阈值校准才是可兑现的那一项。** 在 dev 上按「目标升级率 5%」取分位点（=0.195），
   到冻结 test 上兑现为：升级率 14.9%、**升级精准度 0.429**（基础率 0.149 → **2.9 倍**）、
   召回 0.429。**已把 0.195 定为新的默认阈值。**

5. **但精准度 0.43 意味着叫来的人一多半没事干** —— 所以本闸门的 warn
   **不再送 HITL**，只置 `Trace.needs_review` 供调用方标注。
   弱信号该做的事是提示，不是叫人。顺带修掉一个语义混淆：
   `escalated`（转人工**处置**）与 `needs_review`（答案**复核**）以前是同一个字段。

## 一、项审计：三项各自可辨识吗？

**一个项的取值若在全部样本上恒定，它的权重就不可辨识** ——
填 0 还是填 1，排序结果一模一样。所以拟合之前必须先测这件事。

| 项 | 非零率 | 最小 | 最大 | 标准差 | AUC(该升级) | 可辨识 |
|---|---|---|---|---|---|---|
| T1 不确定度 `1 − 自评置信度` | 0.926 | 0.000 | 0.500 | 0.081 | 0.522 | 是 |
| **T2 无证据（契约要求时）** | **0.000** | 0.000 | 0.000 | **0.000** | — | **否 ❌** |
| T3 检索不确定度 `1 − top/(top+27)` | 1.000 | 0.213 | 0.804 | 0.112 | **0.856** | 是 |

**三项的实际取值区间差了一个量级**（T1 标准差 0.081，T3 是 0.112，而 T1 的**均值**只有 0.077）。
这不是权重能解决的问题 —— 它直接导致下面这条：

```
当前权重下风险分的实际可达区间：[0.053, 0.401]
默认阈值 threshold=0.5 是否可达：❌ 不可达（上界 0.401 < 0.5）
```

**`UncertaintyGate(threshold=0.5)` 在本数据上一条都不会升级** ——
不是"触发得少"，是**恒等于零**。整个 exp9 消融 2445 次运行里，
`uncertainty` 判出 warn 的次数是 **0**。

> 这个 bug 之所以能活这么久，是因为它**完全静默**：
> 不抛异常、不影响任何指标、`risk.blocked()` 也只看 `severity=="block"`（门控是 `warn`）。
> 唯一的暴露方式是**主动去数它触发了几次** —— 而那正是本实验 §1 做的事。

## 二、dev 上拟合权重

dev 47 题、正例 8 条，单纯形网格 231 点（step 0.05），目标 AURC 最小。

| 权重 | dev AURC | dev AUC |
|---|---|---|
| 出厂 (0.4, 0.35, 0.25) | 0.0405 | 0.862 |
| 拟合 (0.1, 0.65, 0.25) | **0.0256** | **0.933** |

**dev 上最优的前 10 组权重（看平台有多宽）：**

| AURC | AUC | (T1, T2, T3) | T1/(T1+T3) |
|---|---|---|---|
| 0.0256 | 0.9327 | (0.10, 0.65, 0.25) | 0.286 |
| 0.0256 | 0.9327 | (0.15, 0.45, 0.40) | 0.273 |
| 0.0256 | 0.9327 | (0.15, 0.50, 0.35) | 0.300 |
| 0.0256 | 0.9327 | (0.20, 0.30, 0.50) | 0.286 |
| 0.0256 | 0.9327 | (0.20, 0.35, 0.45) | 0.308 |
| 0.0256 | 0.9327 | (0.25, 0.10, 0.65) | 0.278 |
| 0.0256 | 0.9327 | (0.25, 0.15, 0.60) | 0.294 |
| 0.0256 | 0.9327 | (0.25, 0.20, 0.55) | 0.313 |
| 0.0256 | 0.9327 | (0.30, 0.00, 0.70) | 0.300 |
| 0.0256 | 0.9327 | (0.30, 0.05, 0.65) | 0.316 |

**这张表比"最优是哪一组"信息量大得多**，它同时说明两件事：

- **T2 的权重从 0.00 到 0.65 全部并列最优** → 完全自由，证实 §1 的"不可辨识"。
- **T1:T3 被死死钉在 0.29 附近（0.273~0.316）** → 数据确实在说一件事：
  出厂的 0.615:0.385 把自评置信度放得太重了。这与 exp8 的诊断一致
  （自评置信度在盲区题上方向是反的：盲区 0.954 vs 可答 0.917）。

> 平台宽 ≠ 结论弱。**平台的形状就是结论**：
> 一个方向（T1:T3 之比）被数据钉住了，另一个方向（T2 的权重）数据完全没说。

## 三、置换检验：这个 dev 最优是真信号还是噪声？

dev 只有 47 题、8 个正例，在 231 个点上搜最优，**随便一组权重都可能在 dev 上碰巧排得很好**。
所以必须跟"纯噪声下能达到的最优"比。

做法：把 dev 标签打乱 2000 次，每次**重新拟合**，得到零分布。

| | AURC |
|---|---|
| **真实 dev 最优** | **0.0256** |
| 置换零分布 · 中位数 | 0.1217 |
| 置换零分布 · 5% 分位 | 0.0702 |
| 置换零分布 · 最小值 | 0.0362 |

**p < 0.0005** —— 真实最优比 2000 次噪声拟合的**最小值**还要好。
**所以 dev 拟合到的不是纯噪声。** 这句话必须说清楚，因为它让第 4 节的负面结论
变得有分量：不是"拟合方法不行"，而是"47 题就是不够"。

## 四、test 上验证：拟合权重没有可证实的增益

| 臂 | AUC | 95% CI | AURC | vs 基线 |
|---|---|---|---|---|
| S0 常数分（零知识基线） | 0.500 | — | 0.149 | 0.000 |
| V0 出厂权重（现状） | 0.775 | [0.590, 0.929] | 0.052 | −0.097 |
| V1 拟合权重（dev 最优） | 0.800 | [0.629, 0.938] | 0.047 | −0.102 |
| T1 只用不确定度 | 0.548 | [0.322, 0.774] | 0.089 | −0.060 |
| T3 只用检索不确定度 | 0.786 | [0.593, 0.941] | 0.051 | −0.098 |
| Oracle 完美排序 | 1.000 | — | 0.012 | −0.137 |

**配对 bootstrap（同一批 test 题，4000 次重采样）：**

```
AUC(拟合) − AUC(出厂) = +0.025   95% CI [−0.092, +0.125]   中位 +0.028
❌ 区间含 0：dev 拟合的权重在 test 上**没有**可证实的增益
```

> **为什么用配对 bootstrap 而不是"看两个 CI 有没有重叠"：**
> 两个臂看的是**同一批题**，AUC 高度相关。各自算 CI 再比区间，
> 是拿独立样本的方法套配对数据 —— 会**低估**差异的精度（区间偏宽，容易误判为"无差异"）。
> 这里两种方法都指向同一结论，但方法本身必须用对。

**另外两个值得记下的观察：**

- **T1 单独用几乎无用**（AUC 0.548，CI [0.322, 0.774] 含 0.5）。
  出厂把 0.4 的权重压在它身上，是**没有任何数据支持的**。
- **T3 单独用 ≈ 融合用**（0.786 vs 0.775）。exp8 曾报告"融合优于任一单信号"
  （分析二 0.012 vs 0.019）；本实验换成**并集标签**后这个优势消失了。
  → **"融合优于单信号"这个结论对标签定义敏感，不稳定。** 如实记录。

## 五、阈值校准：可兑现的那一项

在 dev 上按目标升级率取分位点定阈值，到冻结 test 上兑现：

| 策略 | dev 阈值 | test 升级率 | 升级精准度 | 升级召回 |
|---|---|---|---|---|
| 出厂权重 · 目标 5% | **0.195** | 0.149 | **0.429** | 0.429 |
| 出厂权重 · 目标 10% | 0.189 | 0.191 | 0.333 | 0.429 |
| 出厂权重 · 目标 20% | 0.181 | 0.234 | 0.273 | 0.429 |
| 拟合权重 · 目标 5% | 0.172 | 0.128 | 0.333 | 0.286 |
| 拟合权重 · 目标 10% | 0.169 | 0.128 | 0.333 | 0.286 |
| 拟合权重 · 目标 20% | 0.154 | 0.319 | 0.333 | 0.714 |
| **出厂默认 `threshold=0.5`** | 0.500 | **0.000** | — | — |

**test 基础率 0.149。** 所以「目标 5%」这一档的升级精准度 0.429 是基础率的 **2.9 倍** ——
这是本实验唯一一个**跨划分兑现**的增益，因此定为新的默认阈值。

**两处必须披露：**

1. **阈值跨划分不保值：dev 上 5% → test 上 14.9%，3 倍偏差。**
   根因是分数没有标准化（三项的实际取值区间差一个量级，见 §1），
   绝对阈值因此随样本分布漂移。要根治得先对各项做标准化，
   那需要留存校准集统计量、让门控变成有状态的 —— 本框架暂不做，记为已知局限。
2. **即便校准过，精准度也只有 0.43。** 见下节。

## 六、随之而来的设计决定：弱信号该提示，不该叫人

精准度 0.43 的含义是：**升级 100 次，57 次叫来的人没事干。**
而一次人工介入的成本远高于一条标注。

所以本闸门的 warn **不再送 HITL**，改为置 `Trace.needs_review`：

```
修复前：n_final_review: escalated = state.escalated or has_warn  → after_final → hitl → interrupt
修复后：n_final_review: needs_review = has_warn                   → after_final → END
```

**送 HITL 的强规则原样保留**：`Orchestrator.synthesize` 里 `confidence < 0.3` 那条
（硬规则，不是统计信号）。冒烟测试现在两条路径各走一遍。

**顺带修掉一个语义混淆**：`escalated`（转人工**处置**）与 `needs_review`（答案**复核**）
以前是同一个字段，导致"这题为什么升级"无法归因 —— 而这两类的修法完全不同。

> **这个改动对 exp9 的指标是零影响**，可以验证：修复前该闸门触发 0 次，
> 所以没有任何一条历史记录的行为会因此改变；修复后它触发时也只置 `needs_review`，
> 不改变 `action`。exp9 的 B0~B5 全部结果继续有效。

## 七、复现

```bash
.venv/bin/python scripts/exp8b_gate_calibration.py              # 默认 1000 次置换
.venv/bin/python scripts/exp8b_gate_calibration.py --perms 2000 # 报告用的数字
.venv/bin/python scripts/selftest_guards.py                     # 第 [20] 组守着"阈值可达"
```

**成本**：0 次 LLM 调用（读 exp8 的落盘结果），全量 < 20 秒。
