# 实验 2：歧义策略 —— 该问就问，还是硬猜？

> 要回答的问题：exp3 测出路由层对"缺槽位"的判断不准，exp9 测出**「分层路由 + 澄清」
> 是整套系统里最值钱的一层（+0.180）**。但"澄清"到底是怎么起作用的？
> 是系统**问对了**，还是只要**开口问**就行？多给预算能不能替代问？
>
> 数据：`eval/intent_set.jsonl` 的 test 划分 —— **L3 歧义 30 题（金标 `clarify`）
> + L1 明确 60 题（金标 `answer`）= 90 题**
> 原始结果：`results/exp2_raw.jsonl` · `results/exp2_ambiguity.json`
> 代码：`scripts/exp2_ambiguity.py`（复用 exp9 的 `FlatOrchestrator`，不复制）

## 结论先说

1. **澄清能力是**开关**，不是**策略**——本实验能测的是开关，不是策略。**
   A0/A1 设了 `allow_clarify=False`，它们的澄清率**恒为 0（不是测出来的 0）**。
   所以"A2 比 A0 更爱澄清（19/30，p<0.0001）"是**同义反复**，不是发现。
   真正的结论在 A2 的**绝对值**：L3 澄清 **0.633**（漏 0.367）、L1 误澄清 **0.083**。
   **这一条写在最前面，因为不写就会被读成"主动澄清有效"。**

2. **澄清的收益是净正的，但不大：L3 +19 题，L1 −5 题，净 +14/90。**
   代价还是**负的** —— A2 的 tok/题（734）**低于** A0（923），
   因为澄清时跳过 dispatch（calls/题 1.83 vs 2.77）。
   **开口问既更准又更便宜**，这与 exp9 的 B1→B2 一致。

3. **加大预算被"支配"了：澄清率不升、硬答率反升、成本 ×2.75、延迟 ×2.11。**
   A1（thinking + 32768）相对 A0 只改了 2/30 题的动作，两题都是 `refuse → answer`
   （**更爱硬答**）。**"多给预算"买不到"问对问题"。**

4. **但 H2 的前提在本集不成立 —— 截断根本没发生。**
   六个"臂 × 层"格子里 `截断题率` **全是 0.000**（先验证过 `stop_reason` 是通的：
   把 `max_tokens` 压到 16 会正常返回 `max_tokens`）。
   所以"加大预算压下了截断"这句话**在本集无法检验**。
   > 初版脚本里这行 print **硬编码了"加大预算确实压下了截断"**，
   > 而实测是 0.000 → 0.000。**结论写死在打印里，就一定会和数据脱钩。**
   > 已改成由数字决定的分支（`t0 == 0 and t1 == 0` 时输出"前提不成立"）。

5. **A2 的澄清问题是一个写死的常量，所以本实验**不能**用来评价澄清质量。**
   24 次澄清**全部**是同一句"能否补充一下具体信息？" ——
   因为 exp9 的 `FlatOrchestrator` 把它硬编码在 `scripts/exp9_ablation.py:111`。
   这与**生产路径**（`Orchestrator.route()`）是两条路：生产路径由 LLM 生成问题，
   在 exp9 的 B2~B5 上兜底常量只命中 **0/25、1/28、0/29、0/32**，
   问题都是具体的（"请问您要查哪个部门、哪个时间段（如某月或某季度）的离职率？"）。
   **两条路不要混为一谈**：exp2 测的是"能不能澄清"，不是"澄清得好不好"。

6. **真正的可改进项在路由的歧义判断，两个方向都错，而且金标把答案写出来了。**
   - **漏问（11/30）**：其中 **9 题金标 `missing_slots` 非空**（如
     INT0060「现在离职率多少？」金标缺 `dept, period`），系统仍然硬答。
   - **误问（5/60）**：这 5 题金标 `slots` 是**填好的**、`needs_clarification=false`，
     例如 INT0180「研发中心的人均社保缴纳额是多少？」金标 `slots={"dept":"研发中心"}` ——
     部门已经给了，系统还是问"能否补充一下具体信息？"。
   **两个方向都不是"信息不足"，是路由没用好已有的槽位信号。**

## 一、三臂设计

| 臂 | `allow_clarify` | thinking | max_tokens | 想测什么 |
|---|---|---|---|---|
| **A0** 硬猜（默认预算） | **False** | False | 默认 | 基线：不能问，只能猜 |
| **A1** 加大预算 | **False** | **True** | **32768** | 预算能不能替代问 |
| **A2** 主动澄清 | **True** | False | 默认 | 打开澄清开关 |

**关键设计事实：A0/A1 不能澄清。** 这不是疏忽，是为了隔离"预算"这一个变量 ——
但它同时决定了 **A2 vs A0 的对比是同义反复**（见结论 1）。
`FlatOrchestrator` 从 exp9 复用，**刻意不复制**，保证两处口径一致。

## 二、主结果

**【L3 歧义题】30 题，金标 `clarify` —— 澄清率越高越好**

| 臂 | 澄清率 | 硬答率 | 拒答率 | tok/题 | 截断题率 | 秒/题 |
|---|---|---|---|---|---|---|
| A0 硬猜 | 0.000 | 0.933 | 0.067 | 923 | 0.000 | 6.11 |
| A1 加大预算 | 0.000 | **1.000** | 0.000 | 2534 | 0.000 | 12.88 |
| **A2 主动澄清** | **0.633** | 0.367 | 0.000 | **734** | 0.000 | **4.35** |

**【L1 明确题】60 题，金标 `answer` —— 误澄清率越低越好（防刷分的对照项）**

| 臂 | 正确率 | 误澄清率 | 拒答率 | tok/题 | 截断题率 | 秒/题 |
|---|---|---|---|---|---|---|
| A0 硬猜 | **1.000** | 0.000 | 0.000 | 641 | 0.000 | 6.02 |
| A1 加大预算 | **1.000** | 0.000 | 0.000 | 1789 | 0.000 | 11.94 |
| **A2 主动澄清** | 0.900 | **0.083** | 0.017 | **524** | 0.000 | 5.48 |

**合起来读：**

```
L3：0/30 → 19/30      澄清能力买到 +19
L1：60/60 → 54/60     代价 −6（5 例误澄清 + 1 例拒答）
净：60/90 → 73/90 = +0.144
```

**而成本是负的**（734 < 923 tok/题）：澄清时**不调执行体**，
`calls/题` 从 2.77 掉到 1.83。**这是本实验最干净的一条结论：开口问又准又便宜。**

## 三、H1：该问的问了没有，不该问的问了没有

| | 数值 | McNemar |
|---|---|---|
| L3 澄清率 A0 → A2 | 0.000 → 0.633 | b=0 c=19 **p < 0.0001** |
| L1 误澄清率 A0 → A2 | 0.000 → 0.083 | b=0 c=5 **p = 0.0625** |

**两个 p 值都不能按字面读**：

- **L3 的 p < 0.0001 是同义反复** —— A0 的澄清率恒为 0（开关关着），
  任何"打开开关"的臂都会得到这个 p 值。**它检验的不是策略优劣。**
- **L1 的 p = 0.0625 是"未达显著"** —— 但**方向不能读反**：
  这里我们希望**不**拒绝原假设（即"没有更多误澄清"）。
  p = 0.0625 意味着**有 0.083 的过度澄清，只是 60 题还不足以把它钉死**。
  5 例误澄清在 60 题上就是 8.3pp 的额外代价，**不能因为 p > 0.05 就当它不存在。**

> **方法论提醒**：这个检验里"显著"是**坏事**（显著 = 确实更爱乱问）。
> 把 p 值当成"越小越好"的通例在这里会读反。

## 四、H2：加大预算买不到"问对问题"

| | A0 | A1 | 变化 |
|---|---|---|---|
| L3 澄清率 | 0.000 | 0.000 | **没动**（p = 1.0000） |
| L3 硬答率 | 0.933 | **1.000** | **更糟** |
| L3 截断题率 | 0.000 | 0.000 | **测不到**（前提不成立） |
| tok/题 | 923 | 2534 | **×2.75** |
| 秒/题 | 6.11 | 12.88 | **×2.11** |

**A1 相对 A0 是被支配的（dominated）**：没有任何指标变好，两项显著变差。
只改了 2/30 题的动作，且两题都是 `refuse → answer`（**更爱硬答**）：
INT0095（"人招满了吗"类）、INT0153。

**截断率全 0 是先验证过测量工具的**，不是又一次"声明了但没接线"：

```
max_tokens=16 → stop_reason='max_tokens'  out_tokens=16  truncated=True
max_tokens=32 → stop_reason='max_tokens'  out_tokens=32  truncated=True
```

`stop_reason` 通路是好的；本集的题目与回答都太短，**根本没有触到天花板**。
所以 H2 的原始假设（"加大预算 = 不再截断"）在本集**无法检验** ——
A1 只是花 2.75 倍的钱买了一个更爱硬答的系统。

> **初版脚本在这里犯了一个具体的错**：那行 print 硬编码了
> "（加大预算**确实**压下了截断）"，而数据是 0.000 → 0.000。
> 这是"把结论写死在打印里"的必然下场 —— 结论与数据脱钩时，
> 打印出来的仍然是那句斩钉截铁的话。已改成由数字决定的分支。

## 五、本实验测不到的东西（必须写明，否则会被误读）

1. **测不到澄清质量。** A2 的 24 次澄清**全部**是同一句
   "能否补充一下具体信息？"（`scripts/exp9_ablation.py:111` 硬编码）。
   所以本实验**不能**说"澄清得好"或"澄清得差"。
   **生产路径是另一条**（`Orchestrator.route()`，由 LLM 生成问题）：
   在 exp9 的 B2~B5 上兜底常量命中 **0/25、1/28、0/29、0/32**，问题具体可用。
   → **exp2 的结论只能用于"要不要给澄清能力"，不能外推到"澄清写得好不好"。**
2. **测不到截断。** 见第四节。
3. **L1 的 60 题不能反映"答案质量"。** 判据是 `action == expected`，
   不含答案内容校验。A0 在这 60 题上正确率 **1.000** ——
   但它只是"永远作答"，这不等于答对（与 exp9 第七节第 9 条同一个局限）。
4. **单次运行。** 未做同臂复跑。A2 的 0.633 与 0.083 各只有 19 例和 5 例支撑，
   点估计不稳。exp9 测出的同臂动作差异是 2.7%~7.3%，按这个量级，
   **A2 与 A0 的差距（+0.144）远高于噪声底**，但 A2 自身的绝对水平需要复跑才敢细读。

## 六、可改进项：路由的歧义判断，两个方向都能修

**金标把"缺什么"直接写出来了**（`missing_slots` 字段，只标在 L3 上）。

### 漏问：11/30 该问没问

其中 **9 题金标 `missing_slots` 非空** —— 数据集明说了缺什么，系统仍然硬答：

| 题号 | 问题 | 金标缺 |
|---|---|---|
| INT0060 | 现在离职率多少？ | `dept, period` |
| INT0114 | 研发中心离职率多少？ | `period` |
| INT0141 | 我们部门现在有多少人？ | `dept` |
| INT0182 | 我们这边有多少人？ | `dept` |
| INT0213 | 出勤率是多少？ | `dept, period` |
| INT0221 | 招聘进度怎么样？ | `dept` |
| INT0244 | 平均月薪多少？ | `dept` |
| INT0264 | 上季度离职率呢？ | `dept` |
| INT0267 | 上个季度走了多少人？ | `dept` |

**剩下 2 题（INT0172「加班怎么补？」、INT0239「加班换调休划算吗？」）金标缺槽位为空** ——
它们是**语义歧义**（问的是制度还是个人权益），不是缺槽位。这两题是难例。

### 误问：5/60 不该问却问了

这 5 题的金标 `slots` 是**填好的**、`needs_clarification=false`：

| 题号 | 问题 | 金标 slots | 系统实际 |
|---|---|---|---|
| INT0180 | 研发中心的人均社保缴纳额是多少？ | `{"dept":"研发中心"}` | 误澄清 |
| INT0224 | 查一下市场部的公积金缴存情况 | 有 `dept` | 误澄清 |
| INT0268 | 查一下行政部的公积金缴存情况 | 有 `dept` | 误澄清 |
| INT0296 | 这几个候选人里谁最适合 UI 设计师？ | 有 `job_title` | 误澄清 |
| INT0300 | 看一下研发中心的 offer 接受率 | 有 `dept` | 误澄清 |
| INT0127 | P6 的薪酬带宽是多少？ | — | **误拒答** |

**部门/岗位都给了，系统还是问"能否补充一下具体信息？"** ——
这说明**误澄清不是因为信息不足，而是路由没用好已有的槽位**。

> **两个方向的根因是同一个**：路由的 `ambiguity` 是一次性的 LLM 主观打分，
> 与它自己抽出的 `slots` **没有做一致性检查**。
> 一个便宜的修法是加一条后置判据：**`slots` 已填齐关键字段 → `ambiguity` 上限压到阈值以下**。
> 本实验只做诊断，不实施 —— 改路由 prompt 会让 exp3 的结果失效（同 exp9 §8 第 4 条）。
